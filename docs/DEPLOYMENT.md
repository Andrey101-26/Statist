# Публикация Statist на PythonAnywhere

Сайт должен работать на сервере хостинга независимо от компьютера разработчика. Эта инструкция описывает выбранное размещение; публичный адрес добавляется в README **только после успешного развёртывания и проверки**.

## Что нужно

- Аккаунт [PythonAnywhere Beginner](https://www.pythonanywhere.com/pricing/).
- Одна веб-версия Python 3.11 или новее и виртуальное окружение той же версии.
- Исходный код из `Andrey101-26/Statist`.

На бесплатном тарифе доступен один веб-сервис и 512 MiB хранилища. Срок веб-сервиса — один месяц, затем его необходимо продлить в панели. Условия проверены 19.11.2026: [официальная справка](https://help.pythonanywhere.com/pages/FreeAccountsFeatures/). Это не гарантия бессрочной доступности и не SLA. Важно следить за датой продления перед защитой.

## Первое размещение

В серверной Bash-консоли аккаунта (не на компьютере посетителя):

```sh
git clone https://github.com/Andrey101-26/Statist.git ~/Statist
cd ~/Statist
python3.13 -m venv ~/.virtualenvs/statist
~/.virtualenvs/statist/bin/python -m pip install -r requirements.txt
~/.virtualenvs/statist/bin/python manage.py init-demo
```

`python3.13` — пример: выберите доступную в аккаунте версию и ту же версию при создании Web app. Если GitHub недоступен из консоли аккаунта, код можно загрузить через Files без `instance/`, `.git/`, `.venv/` и `.deps/`.

В разделе **Web** добавьте **Manual configuration**, укажите версию Python и путь виртуального окружения `/home/ИМЯ/.virtualenvs/statist`. В WSGI configuration file, который открывается из Web, оставьте:

```python
import sys
project = '/home/ИМЯ/Statist'
if project not in sys.path:
    sys.path.insert(0, project)
from wsgi import application
```

Замените `ИМЯ` именем аккаунта. Нажмите **Reload**. HTTPS-адрес предоставляет сам хостинг; не нужно запускать `python app.py` и держать открытую консоль.

## Хранение данных

По умолчанию SQLite находится в `/home/ИМЯ/Statist/instance/statist.sqlite3`. Файл базы и ключ сессий сохраняются на сервере между перезапусками приложения. Ключ сессий создаётся один раз в служебных метаданных базы; его не показывают пользователям и не добавляют в GitHub. При необходимости путь базы задаётся `STATIST_DATABASE`, а ключ — `STATIST_SECRET_KEY` в окружении хостинга. Не задавайте новый случайный ключ при каждом запуске worker-процесса.

Учебная онлайн-версия пока использует **общую демонстрационную базу** без авторизации. Посетители работают с одними тестовыми остатками; это не личные кабинеты и не рабочая база благополучателей. Вводить персональные и реальные операционные данные нельзя. Защита CSRF, HTTPS-cookie и проверки остатков не заменяют разграничения доступа.

## Обновление

```sh
cd ~/Statist
git pull --ff-only origin main
~/.virtualenvs/statist/bin/python -m pip install -r requirements.txt
```

Затем нажмите Reload в Web. Не удаляйте `instance/`. Повторный `manage.py init-demo` сохраняет уже существующую демонстрационную базу. Резервные копии SQLite делайте через Python `sqlite3.Connection.backup`, а не копированием файла во время записи.

## Проверка после публикации

1. Открыть выданный HTTPS-адрес из другого устройства; `/healthz` должен вернуть `{"status":"ok"}`.
2. Принять тестовое поступление и убедиться, что остатки изменились.
3. Создать заявку, зарезервировать, подтвердить передачу и открыть лист передачи.
4. Перезагрузить приложение через Web и проверить сохранение операций.
5. Проверить дефицит, отмену и выгрузку CSV.

До выполнения этих проверок развёртывание не считается завершённым.

## Почему не GitHub Pages или бесплатный Render с локальной SQLite

GitHub хранит исходники; Pages не запускает Python-сервер. На бесплатном Render файлы SQLite пропадают при перезапуске или засыпании, а бесплатная PostgreSQL-база истекает через 30 дней. Для текущей версии выбран PythonAnywhere с серверным файловым хранилищем. [Ограничения Render](https://render.com/docs/free)

Официальная инструкция [размещения Flask на PythonAnywhere](https://help.pythonanywhere.com/pages/Flask/).
